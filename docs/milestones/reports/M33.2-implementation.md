## Behaviour implemented

- Changed legality (`src/game/melds/validateMeldExtension.ts`): the extension validator now
  rejects an empty extension, revalidates existing + added physical cards with `validateMeld`,
  requires the stored type (and, for a sequence, the suit) to be kept, and otherwise returns
  that deterministic result. The represented-rank history lock and its exact-replacement
  exception are removed; the now-unused `WILDCARD_POSITION_LOCKED` reason is removed from
  `MELD_VALIDATION_REASONS`.
- Consequences: an active jolly or pinella may change `representedRank`; a same-suit pinella
  may switch between natural two and active wildcard; a stored free wildcard
  (`representedRank: null`) may take a rank — all only when the final sequence is valid.
  Exact-replacement extensions remain legal. Engine (`extendMeld`), UI and bots are unchanged
  and inherit the rule through the shared validator.
- Playtest case `Jolly=4♦, 5♦, 6♦, 7♦, 8♦` + `10♦` → `5♦, 6♦, 7♦, 8♦, Jolly=9♦, 10♦`, same
  physical jolly, no error, turn stays in `action`.
- Docs: `docs/RULES.md` (M20 baseline note, M5 extension paragraph, M15 section rewritten as
  "milestone 15 e variante di prodotto milestone 33.2", deferred-features and classification
  cross-references), `docs/ARCHITECTURE.md` (final-state revalidation, bot heuristic wording,
  persistence invariant), `src/shell/matchPersistence.ts` comment.
- Release metadata: `package.json` / root `package-lock.json` `1.1.2`, README current release

## Known risks and ambiguities

- Removing `WILDCARD_POSITION_LOCKED` from `MELD_VALIDATION_REASONS` is a type-level change;
  no UI text, persistence schema or save data referenced it (reasons are never persisted).
- The spec's AC5 lists "wrong-suit additions" as still rejected. A different-suit **two**
  added to a sequence is not a wrong-suit natural: it is a pinella acting as the wildcard,
  and when the final sequence is valid (e.g. stored active `2♠` + `3♠ 4♠`, add `2♥` →
  `2♥=A♠, 2♠, 3♠, 4♠`) the extension is now accepted, with the previous pinella becoming a
  natural two. This follows the spec's "final-state validity is authoritative" rule; wrong-
  suit naturals remain rejected.
- Bot trajectories change wherever a repositioning extension is now legal (visible in seed
  125). No bot heuristic was changed.
- Previously rejected hand-built stored states (a wildcard stored on an already-covered rank,
  a free wildcard below a complete run) are now accepted when the final cards are valid;
  such states are not produced by the engine.
