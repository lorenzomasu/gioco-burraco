## Behaviour implemented

### Seating and turn flow (AC1, AC2)

- `tableSeats` (`GameTable.tsx`) maps from the existing player order and `teamId`: the
  opponent right after the human on the left, the teammate on top, the remaining opponent
  on the right. Seats render in clockwise document order (left, top, right). No domain
  state changes.
- Active turn: the active seat is gold with a steady halo (animated only without reduced
  motion), a filled avatar and the existing «Di turno» text/`aria-current`; the human's
  hand area gets the same emphasis (`active-player--turn`) on the human's turn. The polite
  turn banner is unchanged and stays authoritative.

### Melds as board state (AC3–AC5)

- `.meld-list` has no max-height/overflow and `.meld__cards` wraps instead of scrolling.
- `meldDensity` (`MeldArea.tsx`) picks `roomy` / `compact` / `dense` per team from public
  counts only (≥7 melds or ≥36 cards → dense; ≥4 melds, ≥18 cards or a ≥10-card meld →
  compact). CSS custom properties per density set tile width, card size, overlap strip,
  pip and corner size. A meld of ≥8 cards spans a whole grid row. Overlap is sized so each
  card's rank/suit corner stays exposed; annotated (wildcard/pinella) cards are wider and
  never covered.
- Narrow meld tiles (container query `meld`): label and extension control share row 1,
  the Burraco badge gets its own row, cards span the tile. The visible extension label
  shortens to «Aggiungi» (≤16rem) or «＋» (≤9.5rem); the accessible name
  «Aggiungi alla calata N della squadra X» and the 44 px target are unchanged. In dense
  areas the type word («Sequenza»/«Combinazione») is visually hidden but stays in the DOM.
- One-screen meld areas (review fix): each team's complete meld area fits within one
  viewport height for the stress fixture at every tested width, so the first and last
  meld of a team are inspectable together; the page may scroll only between table
  regions on narrow layouts. Achieved by:
  - a compact overview for dense boards in narrow meld areas (container query
    `meld-area` ≤ 23rem: phones and the wide-desktop meld columns): meld cards
    2.05×2.85 rem, overlap strip 1.2 rem, corner 0.6 rem, tighter tiles and gaps;
  - a visually compact extension control (1.6 rem) with an invisible hit area that
    keeps 44 × 44 px, so the control no longer sets each tile's label-row height;
  - a one-line meld-area header (kicker and team name share a line) at every width;
  - on compact/dense boards the «Nuova calata» help text is visually hidden (still the
    target's `aria-describedby`) except while a drag makes the target available;
  - wide desktop: narrower seat columns (8.5–10.5 rem) and hub (16–20 rem) widen both
    meld columns. The table keeps `min-height`, never a fixed height or local scroll.

### Followable bot choreography (AC6, AC7)

- `botPlaybackDelay(speed, feedback)` is the single delay function. Normal: 900 ms
  ordinary (`BOT_PLAYBACK_DELAYS_MS.normal`), 1200 ms (`BOT_SIGNIFICANT_STEP_DELAYS_MS`)
  after a meld play/extension, discard or player hand-off, newly reached/changed Burraco
  or pozzetto acquisition — classified only from the committed `TableFeedback` cue. The
  human's discard is a hand-off, so the first bot action waits 1200 ms; a mounted,
  restored or fresh-round pending bot waits 900 ms. Fast stays 150 ms. `Completa subito`,
  speed-change rescheduling and session-replacement cancellation are unchanged (same
  effect/cleanup path). Bot flights stay ≤380 ms, within every normal delay.

## Known risks and ambiguities

- Residual density trade-off: in the compact overview (dense board in a narrow meld
  area) meld cards are 2.05×2.85 rem with a 0.6 rem rank/suit corner (above the existing
  0.56 rem annotation minimum) and a smaller central pip; 12-card sequences may use two
  card rows. No meld, card, annotation or Burraco label is hidden, and no meld scrolling
  of any kind remains for the stress fixture.
- The one-screen guarantee is verified for the stress fixture (7 melds per team, two
  12-card sequences). A still larger board would get the same overview density; beyond
  some size a team area could exceed a very short viewport — not observed in the fixture.
- The extension control's 44 × 44 px target is now a hit area larger than its visible
  1.6 rem box (verified by `elementFromPoint` probes); the visible box is smaller than
  in v1.1.
- The spec's hand-off list does not say whether the human's own discard counts; it is
  treated as a player hand-off (first bot action after the human waits 1200 ms, which
  also satisfies the ≥900 ms requirement).
- Collecting the discard pile is classified as an ordinary step (not in the spec's
  significant list).
- Narrow-tile layout uses CSS container queries; a browser without them falls back to
  the control beside the cards (no information lost).
- The active-seat halo is an infinite CSS animation; reduced motion collapses it through
  the existing global policy.
